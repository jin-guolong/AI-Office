# 工业 B2B 网站项目管理标准

本模板用于统一管理工业机械、电气设备和工业零部件等海外独立站项目。新建网站项目时，应复制 `_Template` 的完整目录结构，并按本文件规则存放资料。所有项目文件应支持追溯、复核、协作和长期运营，不得因优化工作覆盖唯一原始文件或丢失关键业务信息。

## 目录说明

| 目录 | 用途 |
| --- | --- |
| `00_Project` | 项目背景、范围、目标、站点地图、品牌资料、决策记录和项目计划 |
| `01_Current` | 当前网站源文件、页面内容、截图、URL 清单和现状基线 |
| `02_Optimize` | 待审核及已优化的 HTML、页面方案、修改记录和验证结果 |
| `03_SEO` | 关键词、搜索意图、页面映射、审计、元数据、Schema 和内链规划 |
| `04_Content` | 产品、Solution、Application、Case Study、Blog、FAQ 等内容资料 |
| `05_Images` | 原始图片、优化图片、视频、图纸、图表及素材授权记录 |
| `06_Data` | GA4、GSC、CRM、排名、爬虫和其他运营数据 |
| `07_Report` | 月报、PPT、专项分析、汇报附件及最终交付版本 |

## 1. 项目资料管理规则

- 每个客户或品牌使用独立项目目录，不得混用不同客户的资料。
- `00_Project` 必须记录项目名称、网站域名、目标市场、目标客户、核心产品、重点行业、主要竞争对手、项目负责人和更新时间。
- 项目目标应对应可验证的业务结果，例如有效采购流量、询盘数量、询盘质量、重点页面表现和内容覆盖，不使用无法核验的增长承诺。
- 品牌名称、公司介绍、产品参数、认证、专利、案例和客户评价必须标注来源；未经确认的信息标记为 `待确认`，不得作为事实发布。
- 需求、范围、关键决定、风险和审批结果应形成记录，注明日期、负责人和影响范围。
- 账号密码、API 密钥、客户个人信息及其他敏感数据不得直接写入 README、HTML、表格或 Git 仓库。
- 项目资料应使用清晰文件名，避免 `新建文件`、`最终版2`、`最新版` 等无法追溯的名称。

## 2. HTML 文件管理规则

- 当前线上页面、客户原始文件及页面基线统一存入 `01_Current`；优化版本统一存入 `02_Optimize`。
- 修改 HTML 前必须完成以下步骤：
  1. 分析现有页面结构、内容、链接、表单、Schema、脚本和跟踪代码。
  2. 说明发现的问题、修改目标及可能影响。
  3. 创建带日期或版本号的备份，保留可恢复的原始版本。
  4. 在 `02_Optimize` 生成独立优化版本，不覆盖唯一原文件。
- 未经批准不得更改 URL、canonical、重定向、表单提交逻辑、第三方脚本或发布状态。
- 不得删除 GA4、Google Tag Manager、广告转化、CRM、热图等跟踪代码；如发现重复或异常，只记录问题并提出处理建议。
- 不得删除重要产品参数、认证、下载资料、法律声明或客户已有的有效内容。
- 修改后必须检查 HTML 语义结构、Title、Meta Description、H1-H6、canonical、robots、Schema、图片 alt、内部链接、表单、移动端显示和基础可访问性。
- 每个优化版本应附修改记录，列明文件、页面 URL、修改项、原因、验证结果和待确认事项。

## 3. SEO 资料管理规则

- 所有 SEO 策略、关键词研究、搜索意图分析、页面映射、技术审计、内链规划和实施清单存入 `03_SEO`。
- 关键词必须按核心产品、产品型号、应用、行业、Solution、技术问题、比较和品牌意图分类，并匹配唯一的主要承接页面。
- 页面规划必须同时考虑搜索意图、买家决策阶段、内容深度、主题覆盖、内部链接和询盘路径。
- 关键词数据应注明国家或地区、语言、设备、数据工具、查询日期和统计周期；不得把估算数据描述为实际流量。
- GSC、GA4、排名工具和爬虫数据必须区分口径，不得混用点击、会话、用户、询盘和排名等指标。
- 所有建议应明确优先级、目标页面、问题证据、建议动作、预期业务影响和验证方式。
- 不创建多个页面竞争同一主要搜索意图；发现潜在内部竞争时，应先判断保留、合并、差异化或重新映射方案。
- SEO 方案不得包含关键词堆砌、隐藏文本、批量低质量页面、虚假评论或其他操纵性做法。

## 4. 图片管理规则

- 原始素材与网站优化素材必须分开保存；原图不可被压缩版本覆盖。
- 图片按产品、应用、制造、质量、项目案例、公司和内容主题分类，文件名应描述主体与用途。
- 每项素材应尽可能记录来源、拍摄或获取日期、版权或授权状态、适用页面及审批状态。
- 库存图、示意图、效果图、AI 生成图和真实项目照片必须明确区分，不得将非真实素材包装为制造能力、客户案例或检测证明。
- 发布前检查尺寸、比例、清晰度、格式、文件大小、色彩一致性和移动端适配；优先使用适合网页的压缩格式，同时保留高质量原件。
- 图片 alt 应准确描述图中对象及页面语境，不堆砌关键词；装饰性图片使用空 alt。
- 涉及客户设备、铭牌、图纸、人员、厂区或保密项目的素材，必须确认发布权限并处理敏感信息。

## 5. 数据管理规则

- 原始导出数据、清洗数据、分析文件和报告引用数据应分层保存，禁止直接覆盖原始导出文件。
- 数据文件必须注明网站或 Property、来源平台、日期范围、对比周期、时区、筛选条件、币种或单位及导出日期。
- GA4、GSC、CRM、排名和爬虫数据应保留各自原始口径，并在分析文件中说明关联逻辑。
- 分析结论必须可回溯到数据来源；无法验证的数据标记为估算、假设或待确认。
- 报告前检查异常值、重复记录、缺失值、采样、阈值、归因变化和跟踪配置变化。
- 客户联系人、询盘内容、邮箱、电话及商业数据应最小化收集和展示；对外文件应进行脱敏。
- 数据文件名建议采用 `项目-数据源-主题-起始日期-结束日期-版本`，日期统一使用 `YYYY-MM-DD`。

## 6. 报告管理规则

- SEO 月报、运营报告、PPT、专项审计和汇报附件统一存入 `07_Report`。
- 每份报告必须注明项目、报告周期、对比周期、数据来源、筛选口径、制作日期和版本状态。
- 报告内容应围绕业务结果组织：本期目标、关键表现、变化原因、重点页面、询盘或转化、已完成工作、问题风险和下期行动。
- 区分事实、分析判断和行动建议；不能由数据直接证明的因果关系不得写成确定结论。
- 图表应包含标题、指标单位、时间范围和数据来源，避免截断坐标轴或使用误导性比较。
- 对客户展示的内容应使用清晰、专业的商业语言，不出现内部备注、未确认结论、SEO 操作术语堆砌或排名保证。
- 工作底稿、待审版本、客户审阅版本和最终交付版本必须分开命名；已审批版本不得被直接覆盖。
- 最终交付前检查数字一致性、链接、图片清晰度、字体、页面版式、客户名称和保密信息。

## 7. 版本管理规则

- 文档和交付文件建议使用：`项目-页面或主题-YYYY-MM-DD-v01-状态.扩展名`。
- 状态字段统一使用：`draft`、`review`、`approved`、`published` 或 `archived`。
- 小范围修订递增版本号；涉及结构、定位、主要内容、URL、数据口径或设计方向的变化必须创建新版本。
- 重要版本应保留变更记录，包括修改日期、修改人、变更内容、原因、审批人和发布状态。
- 原始文件、已审批文件和已发布文件不得覆盖；废弃版本移入归档并说明替代版本，不直接删除。
- Git 提交应保持单一明确主题，提交信息说明实际变更；提交前检查状态，避免加入凭证、临时文件、无关大文件和客户敏感数据。
- 发布或交付前，应确认使用的是最新已审批版本，并保留回退所需的页面文件、配置和修改记录。

## 使用要求

1. 新建网站项目时复制 `_Template`，并将副本重命名为客户或品牌项目名。
2. 保留本 README 作为项目管理总规则，同时根据项目实际情况补充 `00_Project` 中的项目说明。
3. 文件必须放入对应目录；跨目录引用时使用清晰的相对路径或索引说明。
4. Codex 执行分析、内容、HTML、数据或报告任务时，应先读取本文件及对应子目录 README，再开展工作。
5. 如客户要求与本规则冲突，应记录冲突、风险和最终批准决定，不得静默跳过关键控制步骤。
