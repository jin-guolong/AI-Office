# TKD Optimization Rules for Industrial B2B Pages

## 1. Purpose

TKD means title tag, target keyword/topic, and meta description. These elements must represent the real page, help the correct industrial buyer understand relevance, and remain consistent with visible content. They are not fields for keyword stuffing.

Google may generate title links and snippets from multiple page signals. A supplied title or description is an input, not a guaranteed SERP display.

## 2. Required Inputs

Before writing TKD, confirm:

- Canonical URL and page type
- Primary buyer, target country/language, and buyer stage
- Primary search intent and topic cluster
- Product/category/model/solution/application name
- Verified differentiator or selection value
- Primary CTA
- Existing title, H1, description, and competing internal URLs

Do not finalize TKD when the page itself does not satisfy the intended query. Fix or redesign the page first.

## 3. Title Tag Rules

### Required standard

- Write one unique `<title>` for every indexable priority page
- Describe the page accurately and specifically
- Put the differentiating topic early when natural
- Keep the title consistent with the H1, visible page subject, anchor text, and canonical URL
- Use the brand once, normally at the end, when it adds recognition
- Write for scan clarity; avoid boilerplate that hides the page-specific subject
- Use natural professional English and the target market’s terminology

### Prohibited patterns

- Repeated keywords, location lists, or product synonyms
- Unsupported “best,” “No. 1,” “top,” “leading,” or price claims
- Titles shared across materially different pages
- A model name without product type or context
- A title targeting a product or application not covered on the page
- All caps, excessive punctuation, or promotional symbols

### Working templates

Use only when they remain natural and accurate:

- Homepage: `[Company/Brand] | [Core Product or Manufacturing Capability]`
- Category: `[Product Category] for [Primary Application/Need] | [Brand]`
- Product: `[Product/Model] – [Key Verified Attribute/Application] | [Brand]`
- Solution: `[Solution for Industrial Problem/Application] | [Brand]`
- Case study: `[Solution/Product] for [Application/Industry] – Case Study`
- Guide: `[Specific Buyer Question or Task] | [Content Type/Brand]`

### Acceptance checks

- [ ] Unique among indexable pages
- [ ] Page-specific subject is understandable without the URL
- [ ] Primary intent and entity appear naturally
- [ ] No unsupported claim or keyword repetition
- [ ] Matches visible content and H1
- [ ] SERP preview is checked for likely truncation on common devices; no fixed character count is treated as a Google rule

## 4. Target Keyword and Topic Rules

### Selection hierarchy

Choose targets in this order:

1. Business and product relevance
2. Buyer intent and stage
3. Page type fit
4. Target-market terminology
5. GSC and other demand evidence
6. Ability to provide a better, verified answer

### Required mapping fields

For each page record:

| Field | Requirement |
|---|---|
| Primary topic | One intent-led concept, not a forced exact-match phrase |
| Secondary terms | Close variants, specifications, applications, standards, and buyer language |
| Search intent | Navigational, product/category, solution, comparison, informational, or supplier validation |
| Buyer stage | Discover, evaluate, validate, specify, or inquire |
| Preferred URL | One canonical page |
| Evidence | GSC query data, SERP review, customer questions, sales data, or product taxonomy |

### Usage rules

- Use terminology naturally in the title, H1, opening copy, relevant headings, body, links, and image context
- Cover the entity and decision questions comprehensively instead of repeating an exact phrase
- Keep model numbers, standards, materials, sizes, and application names accurate
- Use regional spelling, units, and standards consistently
- Map variants with the same intent to one page
- Create a new page only for materially different intent, product, application, or market need

### Rejection checks

Reject the target when:

- [ ] It has no connection to the company’s offer or target buyer
- [ ] Another canonical page already satisfies the same intent
- [ ] The page lacks facts needed to answer the query
- [ ] The phrase requires an unsupported claim
- [ ] Search volume is the only justification

## 5. Meta Description Rules

### Required standard

- Provide a unique, page-specific summary for priority URLs
- State what the page offers and why it is relevant to the intended buyer
- Include concrete verified information such as product type, material, application, standard, option, service, or decision value
- Use a CTA only when appropriate to the buyer stage
- Align with visible content; do not add claims absent from the page
- Write natural prose rather than a keyword list

### Recommended content order

`What it is → verified fit/value → useful next step`

Examples of next steps include reviewing specifications, comparing options, downloading a datasheet, discussing an application, or requesting a quote.

### Prohibited patterns

- One description reused across a category or product catalog
- Lists of disconnected keywords
- Unsupported pricing, delivery, certification, or performance claims
- Ranking language or internal SEO instructions
- Descriptions that only repeat the title

### Acceptance checks

- [ ] Unique and accurate for the canonical page
- [ ] Communicates a useful buyer reason to visit
- [ ] Includes at least one verified page-specific detail when available
- [ ] Uses natural language and no keyword list
- [ ] Matches visible content and search intent
- [ ] Preview is checked for likely truncation; no fixed length is treated as guaranteed

## 6. H1 and On-Page Alignment

TKD approval also requires:

- One clear primary H1 in the rendered page
- H1 accurately identifies the page subject
- Title and H1 may differ, but must not target different intents
- Opening content confirms the promise made in the title and description
- Headings reflect real buyer questions and page sections
- The canonical URL, breadcrumbs, internal anchors, and structured data name the same primary entity consistently

## 7. Page-Type QA Standards

### Homepage

- Identifies the company and core manufacturing/product scope
- Does not attempt to target every product keyword

### Category

- Names the full product family
- Differentiates the range by application, material, technology, or selection criteria

### Product detail

- Identifies product/model and a verified distinguishing attribute or application
- Avoids copying category metadata

### Solution/application

- Leads with the industrial problem, process, or application outcome
- Does not present a generic product list as a solution

### Blog/FAQ

- Matches the exact informational task
- Avoids competing with the commercial page for the same primary intent

## 8. Codex Output Format

When recommending TKD, output a table with:

| URL | Page type | Buyer intent | Current title | Proposed title | H1 | Proposed description | Evidence | Risk/notes |
|---|---|---|---|---|---|---|---|---|

Also report duplicates, cannibalization risks, unsupported claims, missing page facts, and URLs that should not be optimized until page content is fixed.

## 9. Final Pass/Fail Checklist

- [ ] Canonical URL and index status are known
- [ ] One primary intent and topic are assigned
- [ ] Title, H1, content, description, and URL represent the same page
- [ ] Title and description are unique
- [ ] Industrial terminology and claims are verified
- [ ] No stuffing, superlatives, or copied boilerplate
- [ ] Metadata supports the buyer’s next decision
- [ ] Internal cannibalization has been checked
